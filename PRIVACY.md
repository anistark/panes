# Panes — Privacy Policy

_Last updated: 2026-04-30_

## Summary

**Panes does not collect, transmit, sell, or share any of your data.**
Everything happens locally in your browser. There are no analytics, no
telemetry, no remote logging, and no third-party services involved.

## What data Panes stores

The only data Panes writes is a single value in
[`chrome.storage.local`](https://developer.chrome.com/docs/extensions/reference/api/storage):

| Key | Value | Purpose |
| --- | ----- | ------- |
| `lastLayout` | `2` or `4` | Restores your most recent layout (2- or 4-pane) the next time you open a split tab. |

This value never leaves your device. It is also wiped if you uninstall
the extension or clear your Chrome local storage.

## What data Panes does **not** store

- The URLs you visit inside panes
- The content of any page you load
- Login credentials, cookies, or session tokens (those remain in your
  browser's normal cookie jar; Panes never reads them)
- Browsing history, click history, search history
- Personally identifying information of any kind

## Permissions and why they're needed

Panes requests the smallest set of permissions necessary to function.
Each one is explained below.

### `declarativeNetRequest`, `declarativeNetRequestWithHostAccess`

Used to remove the `X-Frame-Options` and `Content-Security-Policy`
response headers **only on requests originating from a Panes split-view
tab** (scoped via the `tabIds` condition). This is what lets sites like
GitHub, Hacker News, and Stack Overflow load inside a pane.

The rules are added when you open a split tab and removed when the
split tab closes. They do not affect any other tab.

Panes uses the **declarative** Net Request API, which means Chrome
itself enforces the rules without ever exposing request contents to the
extension. Panes does not see, log, or transmit any HTTP traffic.

### `tabs`

Used to:

- Read the URL of the currently active tab when you open a split, so
  pane 1 can preload that page (`?pane1=<url>`).
- Open a new Chrome tab when you pop a pane out (the `⤴` button) or
  ⌘/middle-click a link.
- Track which tabs are split tabs so that the network-rule scoping
  above stays correct when split tabs are closed.

The URL is used in-process only and never persisted or transmitted.

### `storage`

Used solely to write the `lastLayout` value described above.

### `host_permissions: ["<all_urls>"]`

Required for two reasons:

1. The declarative network rules must be allowed to apply to any URL
   the user might frame inside a pane.
2. The `framebust-guard` content script must be allowed to inject into
   any frame, in order to neutralize JavaScript framebust attempts that
   would otherwise eject the page from the split view.

`<all_urls>` does **not** mean Panes reads the contents of pages you
visit. The content script's only job is to block specific top-frame
navigation attempts; it does not exfiltrate any page data.

## Network requests

Panes itself makes no network requests. The only network traffic is the
normal traffic generated by the websites you choose to load inside
panes — exactly as if you had opened them in regular tabs.

## Third parties

None. Panes has no third-party SDKs, no analytics services, no error
reporting services, and no advertising integrations.

## Children's privacy

Because Panes does not collect any data at all, it does not collect
data from children either.

## Changes to this policy

If the data-handling behavior of Panes ever changes, this document
will be updated and the change announced in the extension's release
notes. Material changes (e.g., introduction of any data collection)
will be opt-in.

## Contact

For privacy questions, please open an issue on the project's
repository.
